# bundlers — Build System Integration Reference

## Purpose

This directory provides isolated bundler integration examples without the
overhead of a complete application. Each subdirectory demonstrates how the
Barrits package-first contract translates to a specific build system's
plugin API.

## Directory Structure

| Subdirectory | Files |
|---|---|
| `vite/` | `vite.config.ts`, `vite-manifest-entry.mjs` |
| `esbuild/` | `esbuild.config.mjs`, `bundler-manifest-entry.mjs` |
| `rollup/` | `rollup.config.mjs`, `bundler-manifest-entry.mjs` |
| `webpack/` | `webpack.config.mjs`, `webpack-manifest-entry.mjs` |

## API Functions Used

| Function | Purpose |
|---|---|
| `defineBarritsPackage` | Declares the shared consumer identity |
| `toBarritsAutomationOptions` | Adapts configuration for each plugin |
| `barritsVitePlugin` | Vite build integration |
| `barritsEsbuildPlugin` | esbuild build integration |
| `barritsRollupPlugin` | Rollup build integration |
| `barritsWebpackPlugin` | Webpack build integration |
| `createBuildManifestSummary` | Summarizes the manifest generated by each build |

## Comparison Methodology

The four configuration files are designed for side-by-side comparison. The
package-first contract (`defineBarritsPackage`) remains identical across
all bundlers; only the plugin interface differs. This demonstrates that the
orchestration boundary is build-system-agnostic.

## Execution

```bash
npm run build:vite      # Build with Vite
npm run build:esbuild   # Build with esbuild
npm run build:rollup    # Build with Rollup
npm run build:webpack   # Build with Webpack
npm run build:all       # Build with all bundlers sequentially
```
